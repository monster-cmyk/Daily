# daily. — 나를 쌓아가는 하루

매일 한 일을 남기고 스스로 돌아보는 개인 기록 웹앱입니다. Pretendard 글꼴, 한국어 화면과 모바일 레이아웃을 제공합니다.

- 날짜별 할 일 추가·완료·삭제와 완료율
- 업무·배움·일상·건강으로 분류하는 하루 기록, 수정·삭제
- 5단계 하루 평가와 자동 저장되는 짧은 회고
- 주간 기록 수, 완료한 일, 평균 평가, 일주일 모아보기
- 연속 기록 일수와 날짜 이동
- JSON 백업·복원, 파일 형식 검사와 교체 전 확인

## 실행

### 어디서 사용하나요?

이 환경의 파일 미리보기 링크는 앱 접속 주소가 아니며, 관리형 브라우저가 로컬 파일 실행을 차단할 수 있습니다. 환경의 Publish는 개발 환경을 보존하는 기능이며 앱을 인터넷에 배포하지 않습니다.

### 인터넷으로 접속하기

GitHub Pages 배포 대상은 `https://monster-cmyk.github.io/Daily/`입니다. 이 주소는 Pages 게시가 완료된 후에 사용할 수 있습니다.

저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정하면 `.github/workflows/deploy-pages.yml`이 `main` 변경 시 앱을 빌드하고 게시합니다. 최초 설정 후에는 Actions에서 **Publish daily. to GitHub Pages → Run workflow**로 실행할 수 있습니다. GitHub Pages를 지원하는 저장소 가시성과 계정 요금제가 필요합니다. 배포를 위해 저장소 가시성을 임의로 변경하지 않습니다.

상대 경로로 빌드하므로 `/Daily/` 아래에서 앱·아이콘·Pretendard 글꼴을 모두 불러올 수 있습니다. 앱을 게시해도 개인 기록은 GitHub에 전송되지 않고 각 브라우저에 남습니다.

### 다운로드해서 사용하기

지금 개인 컴퓨터에서 사용하려면 다음 순서로 실행하세요.

1. 생성된 `Daily.zip`을 컴퓨터에 내려받습니다.
2. 압축을 풉니다.
3. 폴더 안의 `daily.html`을 일반 Chrome 또는 Edge에서 엽니다.

글꼴과 앱 코드가 파일 안에 포함되어 별도 설치나 인터넷 연결이 필요하지 않습니다. 파일 실행·저장 허용 여부는 사용하는 브라우저의 정책에 따라 달라질 수 있습니다. 인터넷 주소로 접속하려면 `dist` 결과물을 정적 웹 호스팅에 별도로 게시해야 합니다.

`daily.html`과 `Daily.zip`은 `npm run build` 또는 `npm run build:standalone`으로 생성됩니다. 소스 코드를 바꾸면 다시 빌드해주세요. 독립 실행 HTML에는 Pretendard 라이선스도 포함됩니다.

### 개발 서버로 실행하기

개발·빌드에는 Node.js 22.12 이상이 필요합니다. 별도 데이터베이스나 API 키는 필요하지 않습니다.

```sh
cd /workspace/Daily
npm ci
npm run dev
```

개발 서버 기본 포트는 `5173`입니다. 특정 포트가 필요하면 `npm run dev -- --port 5173 --strictPort`를 사용하세요.

```sh
npm run build       # TypeScript 검사, 프로덕션 빌드, daily.html 및 Daily.zip 생성
npm run preview     # 빌드한 앱 확인
npm test            # Chromium으로 실제 사용 흐름 검증
```

테스트는 `/usr/bin/chromium`이 있으면 사용합니다. 다른 경로는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정할 수 있습니다. Chromium이 없는 개발 환경에서는 `npx playwright install chromium`을 먼저 실행하세요. 테스트용 Vite 서버는 4173 포트에서 자동으로 실행됩니다.

`npm test`는 독립 실행 파일도 새로 생성하고, 해당 HTML을 별도 자원 요청 없이 실행하여 오프라인 동작과 저장 유지를 검증합니다. 실제 `file:` 주소 탐색도 검사하지만, 관리형 브라우저 정책이 파일 탐색을 차단하는 환경에서는 그 검사만 건너뛰고 사유를 표시합니다. 이 경우 해당 환경의 파일 주소 접근은 검증되지 않은 상태이며, 브라우저 정책을 변경하지 않습니다.

## 기록 저장과 백업

데이터는 `localStorage`의 `daily.journal.v1`에 저장됩니다. **기록은 현재 기기의 현재 브라우저에만 남으며, 계정이나 서버 동기화는 없습니다.** 브라우저 데이터를 지우거나 시크릿 모드를 종료하면 사라질 수 있습니다. 다른 기기로 옮기기 전에는 메뉴의 **데이터 관리 → 전체 기록 백업하기**로 JSON 파일을 보관하세요.

파일로 연 앱과 개발 서버로 연 앱은 서로 다른 저장 공간을 사용합니다. 파일 이름·위치를 바꾸거나 접속 방식을 바꿀 때도 백업·복원을 이용해주세요. 브라우저가 로컬 파일의 저장 공간을 차단하면 저장 경고가 표시되며, 이 경우 개발 서버 방식으로 사용하세요.

백업을 불러오면 확인을 거쳐 현재 기록 전체가 교체됩니다. 잘못된 형식의 파일은 거부하며, 저장된 데이터가 손상된 경우 자동으로 덮어쓰지 않고 원본 백업을 제공합니다. 브라우저 저장 공간에 접근할 수 없거나 용량이 부족하면 저장 실패를 화면에 표시합니다. 백업 파일은 평문이므로 개인 정보가 있다면 안전하게 보관하세요.

하루 평가는 사용자가 직접 고릅니다. 화면의 응원 문구는 미리 준비한 문장이며 AI 평가나 상담 기능은 아닙니다. 외부 API로 기록을 전송하지 않습니다.

## 구조

- `src/App.tsx`: 날짜 탐색, 할 일, 기록, 회고, 주간 통계, 백업 UI
- `src/store.ts`: 데이터 형식, 날짜 계산, 백업 검증
- `src/styles.css`: 데스크톱·모바일 반응형 화면
- `scripts/build-standalone.mjs`: 서버 없이 열 수 있는 `daily.html` 생성
- `tests/standalone.spec.ts`: 실제 파일 주소에서 오프라인 실행·저장·재접속 검증
- `tests/journal.spec.ts`: 저장, 날짜 분리, 편집, 평가, 통계, 백업·복원, 오류 보호, 모바일 테스트

환경은 이미 독립되어 있으므로 기존 `/workspace/Daily` 체크아웃을 그대로 사용합니다. 별도 Git worktree를 만들 필요가 없습니다.
